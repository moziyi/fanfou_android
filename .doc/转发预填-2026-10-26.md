# 转发预填与入口统一（2026-10-26）

## 问题

饭否官方客户端产生的转发在时间线上是**一体化 text**（`评语 转@作者 原文…`，超长按 140 截断），
且同一 status 携带 `repost_status_id` / `repost_status` 引用字段（实证：仓库抓包样例
`StatusQuoteDisplayTest.kt` 的 4 条野生 golden 数据全部如此）。

本客户端当前：

- 两套转发入口不一致：Timeline / Detail / Mentions 用 `RepostDialog`（空输入框、无计数器），
  Search / Shell 路由到 `compose?repostOf=` 页。
- 输入框不预填"转@昵称 原文"；空评论提交时只合成 `转@昵称`，没有原文，与官方形态不符。

## 方案（已获用户批准）

1. **统一入口**：删除 `RepostDialog`，三个屏幕的 `onRepost` 由 MainShell 统一路由到
   `compose?repostOf=<id>`（复用 ContextBanner、按目标草稿 `repost:{id}`、140 计数器）。
2. **预填**：`ComposeViewModel` 在 `repostOfId` 有值且该目标**无已存草稿**（或草稿为空白）时，
   预填 `转@{screenName} {原文}`；总长 >140 时按 Unicode 码点截断原文（不加省略号，与野生链条一致）；
   原文为空则填 `转@{screenName}`；screenName 拿不到则不预填。有草稿则恢复草稿。
   预填逻辑为纯函数 `StatusText.repostPrefill(screenName, originalText)`，带单测。
3. **光标**：停在文本起点（`TextRange(0)`），用户直接在"转"字前输入评语。
4. **提交**：整段文本作为 `status` 提交，并保留 `repostStatusId` 建立引用关系；
   `StatusRepository.post` 的空文本合成（`转@昵称` / `转发`）保留为防御性后备。

## 验证

- 单测：`StatusTextRepostPrefillTest`（正常 / 截断 / 空原文 / 空昵称 / emoji 代理对）。
- 构建与全量单测通过。
- 真机验证（用户执行）：带评论转发一条 → 确认输入框预填与光标位置、发出的消息在
  网页端形态为一体化文本且带引用；随后删除还原。
