# 饭否 App 功能打磨设计方案（三项）

- 日期：2026-10-21
- 状态：已获用户批准，进入实现
- 范围：① 随便看看不缓存 ② 搜索功能（挂到底部导航） ③ 资料编辑

---

## 0. 本方案基于的实测事实

所有结论来自 2026-10-21 的真机 token 实测与 wiki 抓取，不是文档推断。

| 事实 | 证据 |
|---|---|
| `GET /search/public_timeline.json?q=&count=` 可用 | 返回标准 status 数组（含 `user`） |
| 搜索分页只能用 `max_id` | `page=1` 与 `page=2` 返回**同一批 id**；`max_id=<最旧 id>` 返回严格更早的 3 条、无重叠 |
| 搜索结果正文带 HTML 标记 | JSON 中是 `...&lt;strong&gt;成都&lt;/strong&gt;...`（实体 + 高亮标签，不能直接显示） |
| 空 `q` → HTTP 404 | 实测 |
| **用户搜索不可用** | `search/users.json` 三种参数组合均返回**空响应体** |
| `account/update_profile` | 参数 `url / location / description / name / email`（全可选），返回 user（200） |
| `account/update_profile_image` | 参数 `image`（**必选**，multipart），返回 user（200） |
| 没有性别更新接口 | wiki 参数表无 `gender` |
| 头像只有 48px / 96px 两档，**无原图** | `profile_image_url`(s0) / `profile_image_url_large`(l0) |
| 头像 URL 带版本戳 | `.../zc.jpg?1564334108` → 更新后戳会变 → URL 变 → Coil 缓存自动失效 |

## 1. A：随便看看不缓存

### 1.1 目标
「随便看看」（public timeline）的条目**不落本地库**：进程重启后不留任何痕迹。

### 1.2 方案：PUBLIC 走纯内存时间线

| 点 | 做法 |
|---|---|
| 数据源 | `MutableStateFlow<List<StatusUi>>`（上限 300 条，超出丢尾） |
| 刷新 | 拉完整首页 → **整体替换**（不可变数据，不就地修改） |
| 翻页 | `max_id` → 追加 + 按 id 去重 |
| 落库 | **完全不写** `timeline_entry` / `status` |
| 对账 | PUBLIC 不需要（每次刷新整体替换） |
| 回复父帖 | 只读内存解析：父帖按需 `statuses/show` 拉取后放进内存 Map（上限 100），**不落库** |
| 收藏 | 仍写 `favorite_override`（按 status id 的独立表）；内存列表构建时套用覆盖（与 Room 的 LEFT JOIN 语义一致） |
| 冷启动 | PUBLIC 为空，进入时自动刷新 |

### 1.3 历史数据清理
Room 升到 **v3**：

```sql
DELETE FROM timeline_entry WHERE timelineType = 'public'
```

残留的 `status` 行由既有 `pruneOrphans()` 在下一次首页刷新时回收（回复父帖受 `IS NOT NULL` 条件保护，不受影响）。

### 1.4 取舍

| 方案 | 采用 | 理由 |
|---|---|---|
| 纯内存 | ✅ | 语义精确：重启后什么都不留 |
| 继续写 Room、每次替换整页 | ❌ | 重启后仍显示上次条目 → 仍是缓存 |
| 只清旧条目 | ❌ | 同上，且持续写盘 |

### 1.5 明确代价
- 随便看看**离线不可用**（这正是它的语义）。
- 点进某条详情仍会缓存**那一条**（详情页与其它时间线共用同一路径，单条，可接受）。
- 收藏的星星：会话内立即生效；重启后若该条不在缓存中则不显示（收藏本身在服务端）。

## 2. B：搜索（独立入口，底栏第 3 位）

### 2.1 导航调整

| 位置 | 现状 | 改为 |
|---|---|---|
| 1 | 首页 | 首页（不变） |
| 2 | @我 | @我（不变） |
| 3 | 私信 | **搜索**（`Icons.Filled.Search`） |
| 4 | 我 | 我（不变） |

- 私信**已经**在我页有入口（`MeEntry("私信")`），无需新增；`dm` 路由降为非底部目的地。
- **未读徽标跟着搬家**：私信的未读数从「私信」Tab 移到「我」Tab；我页的「私信」行同时显示条数。
- 搜索页是顶层目的地：切走再切回**保留查询与结果**（ViewModel 按目的地作用域）。

### 2.2 交互
输入框自动聚焦 → IME「搜索」键提交 → 结果列表（复用 `StatusCard`）→ 滚到底用 `max_id` 加载更多 → 返回/清除回到普通状态。
状态齐全：空查询（提示「输入关键词」）/ 搜索中 / 无结果（「没有找到相关消息」）/ 失败可重试。

### 2.3 两个技术要点
1. **关键词高亮**：`&lt;strong&gt;关键词&lt;/strong&gt;` → 解码 HTML 实体 → `AnnotatedString` 加粗。抽为纯函数并写单测（实体解码、标签、多关键词 `q=a|b`）。
2. **结果不落库**：与 A 的语义一致，检索结果是临时的。

### 2.4 取舍

| 备选 | 采用 | 理由 |
|---|---|---|
| 底栏独立入口 | ✅ | 用户指定；可发现性好，且不占随便看看的布局 |
| 顶栏搜索图标 | ❌ | 用户指定底栏 |
| 随便看看内常驻搜索栏 | ❌ | 常驻占空间、与滚动争位置 |
| 搜索结果落库 | ❌ | 与 A 的语义一致 |

### 2.5 不做
- **用户搜索**：服务端返回空体（实测），无法实现。
- **搜索某人的消息**（`search/user_timeline` 可用）：暂无自然入口，后续可挂到用户页。

## 3. C：资料编辑

### 3.1 入口与字段
我页头部 →「编辑资料」。

| 字段 | 接口参数 | 说明 |
|---|---|---|
| 头像 | `image`（multipart） | 点选图、预览、可取消 |
| 名称 | `name` | 单行 |
| 自述 | `description` | 多行，带字数 |
| 所在地 | `location` | 单行 |
| 自定义网址 | `url` | 单行 |
| 邮箱 | `email` | 单行（当前账号为空） |
| 性别 | — | **只读**（无更新接口） |

### 3.2 保存流程
头像有变化 → 先 `account/update_profile_image`（multipart `image`）→ 再 `account/update_profile`（字段）→ 成功后返回。
失败时**分别报告**两步的结果（头像已换但字段没存，不能笼统说「保存失败」）。

### 3.3 状态一致性
成功后 `users/show` 拉最新 user → 更新 `TokenStore` 会话（`SelfUser`）→ 更新 `user` 表缓存 → 我页与各卡片立即反映。
头像 URL 因版本戳变化而改变 → Coil 缓存自动失效，**不需要**手工驱逐。

### 3.4 写验证方案（用户已批准）
| 步骤 | 目的 | 风险 |
|---|---|---|
| ① **等价写**：读出当前 name/location/description/url/email 原样提交 | 证明接口可用、字段语义正确（返回 user、资料不变） | 无（值完全一致） |
| ② **空/无效图片**提交给 `update_profile_image` | 证明端点、multipart 字段名 `image`、签名链路正确（预期 4xx，不改头像） | 无 |
| ③ 真实换头像 | 由用户自己在 App 里换一次（产品流程本身） | 用户自愿 |

> 注：服务端**不提供头像原图**（只有 48/96px 两档），因此「上传测试图再还原」实为用 96px 覆盖原头像、永久降质，不采用。

## 6. 实施与验证记录（2026-10-21 ~ 10-22）

### 6.1 A：随便看看不缓存 ✅
- `PublicTimelineSource`：内存列表，刷新整体替换、翻页追加去重、上限 300 条
- 回复父帖只读解析：库里有的直接读（不写入），没有的拉取后放内存
- 收藏仍写 `favorite_override`（真机验证：公开时间线里收藏 → 覆盖表写入 → 重启后仍在）
- Room 升 v3：`DELETE FROM timeline_entry WHERE timelineType='public'`（真机验证 user_version=3、public 条目 0 条）
- 残留的 `status` 行由 `pruneOrphans()` 回收（真机：首页刷新后孤儿行归零，回复父帖受 `IS NOT NULL` 保护）

### 6.2 B：搜索 ✅
- 底栏第 3 位改为「搜索」，私信移入「我」页（原本就有入口），未读徽标跟着搬到「我」
- 端点 `search/public_timeline.json`；`page` 被服务端忽略，用 `max_id` 翻页（实测）
- 高亮：服务端返回 `&lt;strong&gt;词&lt;/strong&gt;`，`SearchHighlight` 解码实体并切分（6 例单测）
- 真机：搜 "linux" → 结果按词加粗 ✓；滚到底自动翻页 ✓；切走再切回保留结果 ✓

### 6.3 C：资料编辑 ❌ 已按用户要求砍掉
**实测结论（2026-10-21/22，写接口的真实行为）**：
| 端点 | 行为 |
|---|---|
| `POST account/update_profile.json` | **200 但不写入**：返回值仍是旧值（name/location/url/description 逐个验证：写临时值 → 读回旧值 → 响应也回旧值） |
| `POST account/update_profile_image.json` | **404「上传照片失败」**：jpg/png、96px/480px、字段名 image/photo/upload 全部试过 |
| `POST account/update_profile_colors.json` | ✅ **真正写入**（改 `profile_background_color` → 读回生效 → 还原成功） |
| 其它候选端点（users/update、account/update、account/profile、settings/profile、account/update_user_info） | 全部 400「参数错误」 |
| `description` 的其它字段名（desc/intro/bio/note/status/signature/memo） | 全部无效（写入被丢弃） |

结论：饭否的 API **不再支持修改名称与头像**，唯一还能写的是网页资料配色。
用户决定：**砍掉整个资料编辑功能**（屏幕、入口、API、仓库、模型字段全部移除），不保留半残的死路径。
（配色接口曾短暂实现，因功能整体砍掉而一并删除；上面的实测结论保留在本文档与长期记忆里。）

### 6.4 新增：查看收藏 ✅
- 入口：用户主页第 4 个标签「收藏」，与「消息 / 关注 / 粉丝」并列；**只在自己的主页出现**（收藏是私有的，`favorites/list` 永远返回 token 所有者的收藏）
- 端点 `GET favorites/list.json?count=&page=`（实测：可分页，返回标准 status 数组）
- 列表不缓存：收藏可能在网页端被改动，过期的列表比短暂的等待更糟
- 卡片只显示星标（`showReplyRepost = false`），点星取消收藏 → 服务端 `favorites/destroy/{id}.json` 成功后条目移出列表；失败则保留条目
- 真机验证：标签页出现 ✓、列表显示收藏内容 ✓、取消收藏 200 且条目消失 ✓、服务端收藏数归零 ✓
