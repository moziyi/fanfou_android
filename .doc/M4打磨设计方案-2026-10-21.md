不在范围内（另议）：主题切换、搜索、资料编辑、通知开关。

## 2. 已验证的接口事实

| 事实 | 证据 |
|---|---|
| `POST /photos/upload.json` 为 multipart，字段 `photo`（文件）+ `status`（正文） | nofan 2.1.2 源码：`ff.post('/photos/upload', { photo: fs.createReadStream(path), status })` |
| 该接口**自己直接发出状态**，不是「先传附件再发状态」 | 实测：只传 `photo` → 服务端生成状态 id `fDOhja2MtBo`，`text` 为默认「上传了新照片」，带完整 user/source/location |
| 返回体是标准 status 对象 | 同上；可直接复用 `StatusRepository.post` 的缓存写入 |
| 接口不接受 `in_reply_to_status_id` / `repost_status_id` | 请求签名只有 photo + status |
| 3.2 MB 原图可直传 | 实测上传 4000×3000 / 3.2 MB 成功 |

## 3. M4-1 图片发布

### 3.1 交互

```
编辑器（仅「新建推文」）
  [文本框……] [140 字计数]                    现有
  [🖼]                                      新增：选图按钮
  选中后 → 缩略图预览（右上角 × 移除）
  发布时 → 「上传中 42%」→ 成功 → 沿用现有 posted 流程（写缓存 + 返回）
```

- 选图：`ActivityResultContracts.PickVisualMedia`（Android 13+ 系统照片选择器，
  12 及以下自动回落 `ACTION_OPEN_DOCUMENT`）→ **不需要任何存储权限**。
- 压缩：`inJustDecodeBounds` → `inSampleSize` → 长边 ≤ 2048 px → JPEG q85
  （3.2 MB → 300–800 KB）。**HEIC 解码失败时回落为原图直传**（API 26/27 不支持 HEIC）。
- 进度：自定义 `RequestBody.writeTo` 回调上报百分比。
- 失败：保留正文与已选图片（同一会话内 URI 仍有效），显示服务端原文，可直接重试。
- 回复 / 转发模式**隐藏选图按钮**（接口不接受这两个参数，且服务端本就会剥离回复关联）。

### 3.2 关键实现点：multipart 的 OAuth 签名

现有签名拦截器只收集 query 与 `FormBody` 的参数。multipart 请求里，参与签名的只有
**文本字段**（`status`），文件部分不参与（RFC 5849 对 multipart/form-data 的规定）。

做法：
- 新增 `TextRequestBody`：持有文本内容的 `RequestBody`，用 `MultipartBody.Part.createFormData`
  包装后，拦截器可从 `part.body` 直接读到文本。
- 拦截器新增分支：`request.body is MultipartBody` → 遍历 `parts`，取
  `body is TextRequestBody` 的部分，从 `Content-Disposition` 解析字段名，取其文本作为参数。
- 签名 base string 的 URL 部分用 `http://api.fanfou.com/photos/upload.json`（沿用本项目既有约定：
  网络走 HTTPS，签名用 HTTP）。

### 3.3 取舍

| 方案 | 结论 |
|---|---|
| 复用 `photos/upload` 单请求 | ✅ 采用：一次往返，失败粒度清晰 |
| 先发文字再传图 | ❌ 会产生两条状态 |
| 原图直传 | ❌ 移动网络体验差；2048 px 远超展示需要（最大 1080 px 宽） |
| 保存图片副本再上传 | ❌ 多一次磁盘 IO 与清理逻辑 |

### 3.4 测试

- 单测：采样尺寸计算（纯函数）、multipart 字段名与 MIME、签名参数收集（拦截器级）。
- 真机：选图 → 预览 → 发布 → 时间线出现带图卡片 → API 核对 text + photo → 删除。

## 4. M4-2 草稿箱

### 4.1 现状

`draft` 表已有 `id / text / inReplyToStatusId / repostStatusId / updatedAt`，按上下文分 id
（`composer` / `reply:{id}` / `repost:{id}`）防抖自动保存。缺的只是「能看见它们」。

### 4.2 设计

- `DraftDao.list(): Flow<List<DraftEntity>>`（`ORDER BY updatedAt DESC`）+ `DraftRepository.observe()`。
- 「我」页新增入口 **草稿箱**（显示条数）。
- 列表行：正文预览 + 上下文徽标（`回复 @xxx` / `转发 @xxx`）+ 相对时间 + 右侧删除。
- 点击 → 按草稿类型路由到对应编辑器，编辑器按 id 恢复内容。
- 删除：即时删除 + Snackbar，不做二次确认（草稿可重写，误删成本低）。
- 空态：「没有草稿」。

### 4.3 取舍：图片要不要进草稿

| 方案 | 结论 |
|---|---|
| 草稿只存文本，图片仅当前会话有效 | ✅ 采用 |
| 把图片复制进 `filesDir/drafts/`，草稿存路径 | ❌ 为罕见路径引入文件生命周期，清理失败即泄漏 |
| 直接存 `content://` URI | ❌ 进程重启后授权失效，草稿打不开 |

对应 UX：带图离开编辑器时正文进草稿、图片丢弃，编辑器内提示一次「图片不会保存到草稿」。

## 5. M4-3 遗留缺口

### 5.1 远端删除的推文仍留在本地

**规则**：手动下拉刷新拿到完整页面后，对「落在本次页面窗口内（`rawid >= 本页最旧 rawid`）
却不在页面里」的条目做对账删除。

**豁免**：饭否会把新嘟「审核中」持有 3–17 分钟，这期间它们不在 `home_timeline` 里，
但本地已乐观插入过 → **作者是自己且创建于 60 分钟内**的条目不参与对账。

实现：
- 纯函数 `TimelineReconciler.staleIds(cached, pageIds, minRawid, recentOwnIds)`（可单测）；
- `StatusDao.deleteTimelineEntries(type, ids)` + 既有 `pruneOrphans()`（其 `IS NOT NULL` 条件不动）；
- 只删 `timeline_entry`，不直接删 `status`（同一条可能还在 `@我` 里）；
- 只在**手动刷新**后对账，自动刷新与翻页不触发。

### 5.2 30 秒刷新去重

设计 §7.3 承诺未实现：`ON_RESUME` 与下拉都会打网络。
修法：`refresh(force)`——手动下拉永远执行；`ON_RESUME` 的自动刷新在距上次成功 < 30 s 时跳过。
不静默吞用户手势。

### 5.3 小项

- 「我」页加「关于 / 版本号」。
- 编辑器发布失败保留正文（现状已如此，回归确认）。

## 7. 风险

| 风险 | 应对 |
|---|---|
| `photos/upload` 的 140 字超限行为未实测 | B1 第一步实测，不靠假设 |
| multipart 签名规则与表单不同，服务器拒签 | 实测失败会立刻返回 `401 Invalid signature` 并回显期望 basestring，据此调参 |
| 大图 OOM | 两段解码（`inJustDecodeBounds` + `inSampleSize`），采样前不分配整图 |
| 对账误删 | 「窗口内 + 自己 60 分钟豁免」双重约束，且只删 `timeline_entry`；单测覆盖四种组合 |

## 8. 已确认的决策（2026-10-21）

1. 图片发布按本方案（单请求、2048 px/q85、仅新建推文可配图）。
2. 草稿箱只存文本，图片不入草稿。
3. 主题保持现状（跟随系统 + 动态取色），M4 不做主题改动。
